# Data Model

**Product:** Financial Data Platform  
**Owner:** Product and Engineering  
**Last updated:** 6 January 2026  

## 1. Purpose

Define the core entities and relationships required by the Financial
Data Platform.

## 2. Core entities

### Company

Represents a legal or publicly listed company.

```text
company_id
name
legal_name
country
sector
industry
status
created_at
updated_at
```

### Exchange

Represents a financial exchange or trading venue.

```text
exchange_id
name
mic_code
country
timezone
currency
status
```

### Instrument

Represents a tradeable financial instrument or listing.

```text
instrument_id
company_id
exchange_id
symbol
name
isin
asset_class
currency
status
created_at
updated_at
```

`instrument_id` is the internal identity used by the platform. Provider
symbols must not be used as the primary internal identity.

### Provider Instrument Mapping

Maps an external provider symbol to an internal instrument.

```text
instrument_id
provider
provider_symbol
valid_from
valid_to
created_at
```

### Data Source

Represents an external provider.

```text
data_source_id
name
provider_type
base_url
status
created_at
```

### Dataset

Represents a type of data collected by the platform.

```text
dataset_id
name
domain
description
schema_version
status
created_at
```

Examples:

```text
ohlcv
orderbook_snapshot
orderbook_event
fundamentals
news
filings
macro
```

### Ingestion Job

Represents one execution of a data-collection operation.

```text
job_id
data_source_id
dataset_id
job_type
status
started_at
completed_at
records_received
records_valid
records_invalid
records_duplicate
records_written
error_message
created_at
```

Possible statuses:

```text
PENDING
RUNNING
SUCCESS
PARTIAL
FAILED
```

### Data Quality Result

Stores the quality outcome of an ingestion job.

```text
quality_id
job_id
dataset_id
records_received
records_valid
records_invalid
records_duplicate
quality_score
validation_summary
created_at
```

## 3. Entity relationships

```text
Company
  └── has many Instruments

Exchange
  └── lists many Instruments

Instrument
  └── has many Provider Instrument Mappings

Data Source
  └── produces many Ingestion Jobs

Dataset
  └── is processed by many Ingestion Jobs

Ingestion Job
  └── produces one Data Quality Result
```

## 4. Storage ownership

### PostgreSQL

PostgreSQL stores:

```text
companies
exchanges
instruments
provider instrument mappings
data sources
datasets
ingestion jobs
data quality results
```

### Object storage

Object storage stores:

```text
raw provider responses
processed Parquet files
rejected records
quality reports
documents
```

### DuckDB

DuckDB queries:

```text
processed Parquet
historical OHLCV
future historical market datasets
```

## 5. Phase 1 entities

Phase 1 requires:

```text
companies
exchanges
instruments
provider instrument mappings
data sources
datasets
ingestion jobs
data quality results
```

Phase 1 does not yet require relational tables for:

```text
order books
fundamentals
news
filings
macro data
```

Those datasets will receive detailed data contracts before implementation.

## 6. Identity rules

Internal identities shall be stable and generated by the platform.

Provider symbols shall be stored as external mappings.

The following values shall not be treated as universal identities:

```text
ticker symbol
provider symbol
company name
instrument display name
```

## 7. Historical market-data identity

A normalized OHLCV record is uniquely identified by:

```text
instrument_id
timestamp
timeframe
```

The source provider and ingestion job should be retained as metadata,
but they do not change the logical identity of the market-data record.
